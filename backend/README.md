# Серверная часть и веб-панель (Django)

Сервер приложения: REST API для мобильного приложения и веб-панель администратора на Django Admin. Запуск — см. [README в корне](../README.md#сборка-и-запуск).

## Структура

```
backend/
├── manage.py
├── requirements.txt          зависимости
├── requirements-dev.txt      + инструменты проверки (pytest, ruff)
├── pyproject.toml            настройки pytest и ruff
├── Dockerfile                образ сервера приложения (Gunicorn)
├── autoschool/               настройки Django-проекта
│   ├── settings.py             БД, приложения, сессии, токены (из переменных окружения)
│   ├── urls.py                 /admin/ и /api/v1/
│   ├── wsgi.py, asgi.py
├── apps/                     модули системы (см. таблицу ниже)
│   └── <модуль>/
│       ├── models.py           таблицы модуля
│       ├── serializers.py      JSON ⇄ модели
│       ├── views.py            обработчики запросов API
│       ├── urls.py             маршруты модуля
│       ├── admin.py            экраны веб-панели
│       └── migrations/         миграции БД
└── tests/                    тесты
```

## Подсистема записи

```
apps/scheduling/services/
├── facade.py         BookingFacade — по одному методу на сценарий: закрепление
│                     инструктора, запись, смена статуса записи, оценка занятия
├── repositories.py   StudentRepository, SlotRepository, BookingRepository, ReviewRepository
├── policies.py       BookingLimitPolicy — «Стратегия» для правил записи филиала
├── events.py         EventPublisher — «Наблюдатель» для действий после изменения записи
└── exceptions.py     исключения подсистемы → коды ошибок API 409 / 422
```

Обработчики в `views.py` обращаются только к фасаду; классы соответствуют диаграмме классов ЛР 4 (рис. 3.1), таблицы — логической модели данных (рис. 1.2), маршруты — табл. 2.1 и [openapi.yaml](../docs/04-architecture/openapi.yaml).
